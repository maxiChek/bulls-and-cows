# Design

## Architecture

Приложение построено с упором на принципы функционального программирования.

- **Core Logic**: Чистые функции (`generateSecret`, `evaluateGuess`, `isValidGuess`, `countPossibleSecrets`) полностью отделены от пользовательского интерфейса и не имеют побочных эффектов. Зависимости (например, генератор случайных чисел) внедряются через аргументы, что делает код легко тестируемым.
- **Core Logic**: Файл `ui.ts` управляет DOM-деревом и состоянием игры. Обновления состояния происходят иммутабельно — создаются новые объекты вместо изменения существующих.
- **Build**: Для разработки и сборки используется бандлер Vite.

## Core Functions

### `createDigitValidator(base)`

Каррированная фабрика функций, которая возвращает валидатор для конкретной системы счисления. Проверяет, является ли отдельный символ допустимой цифрой для этой базы.

### `isValidGuess(guess, length, base)`

Проверяет корректность догадки пользователя. Проверка идет по трем критериям:

1. Длина догадки.
2. Все символы допустимы для выбранной базы (используется `createDigitValidator`).
3. Все цифры в догадке уникальны.

### `generateSecret(length, base, random)`

Чистая функция, генерирующая секретный код. Использует внедренную функцию `random` (вместо прямого вызова `Math.random`), что гарантирует предсказуемость в тестах. Уникальность цифр обеспечивается выбором из уменьшающегося пула доступных символов.

### `evaluateGuess(secret, guess)`

Сравнивает догадку с секретным кодом. Возвращает объект с количеством `bulls` (быки — цифра верная, позиция верная) и `cows` (коровы — цифра верная, позиция неверная). Реализовано через функции высшего порядка (`reduce`, `filter`), что гарантирует правильную обработку повторяющихся цифр в догадке.

### `countPossibleSecrets(length, base, moves)`

Подсчитывает, сколько возможных секретов осталось с учетом истории ходов. Использует рекурсию для генерации всех валидных комбинаций и фильтрует их на основе оценок предыдущих ходов. Для оптимизации применяется мемоизация.

## Testing

Ядро логики полностью покрыто тестами с использованием Jest (через `ts-jest`). Тесты следуют циклу TDD (Red-Green-Refactor) и охватывают граничные случаи, такие как повторяющиеся цифры, невалидные базы и математически корректный подсчет перестановок.
